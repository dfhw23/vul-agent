```

```json

```

```

```

```

```json
{"code":200,"data":["1","5.7.34","testdb"]}
```

**步骤4**: 提取数据
```

Host: target.com
```

## CVSS评分速查

| 分数 | 等级 | 描述 |
|------|------|------|
| 9.0-10.0 | 严重 | Critical |
| 7.0-8.9 | 高危 | High |
| 4.0-6.9 | 中危 | Medium |
| 0.1-3.9 | 低危 | Low |
| 0.0 | 信息 | Info |

### 评分要素

**基础分数（Base Score）**：

- **攻击向量（AV）**：网络(N)/邻接(A)/本地(L)/物理(P)
- **攻击复杂度（AC）**：低(L)/高(H)
- **所需权限（PR）**：无(N)/低(L)/高(H)
- **用户交互（UI）**：无(N)/需要(R)
- **影响范围（S）**：未改变(U)/改变(C)
- **机密性（C）**：无(N)/低(L)/高(H)
- **完整性（I）**：无(N)/低(L)/高(H)
- **可用性（A）**：无(N)/低(L)/高(H)

在线计算器：https://www.first.org/cvss/calculator/3.1

## 报告生成指南

### 报告语言规范

1. **客观描述**：使用技术性语言，避免主观判断
2. **准确复现**：每个漏洞都必须能按步骤重现
3. **具体建议**：修复建议要可执行，避免空洞建议
4. **专业格式**：统一术语和格式

### 报告内容要求

✅ 必须包含：
- 漏洞位置（URL/参数）
- 复现步骤（详细到点击）
- 危害说明（结合业务）
- 修复建议（具体代码示例）

❌ 不要包含：
- 漏洞利用代码（仅描述原理）
- 攻击者视角的炫耀性语言
- 不确定的推测
- 与漏洞无关的内容
